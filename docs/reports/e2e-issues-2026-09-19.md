## 三、本轮已完成的修复

### F1　`ldc` 类字面量降级为 null（对应原「缺口 A1」）

**先前判断有误**：原以为「调用链层漏收类」。实测根因在**指令转译层**——
`codegen/instr/sim/consts.py` 的 ldc 分支把类字面量降级为
`Object::default()`（null），任何对它的调用都 NPE 或静默取默认值。

改动 3 处：

1. `codegen/instr/sim/consts.py`：`comment.startswith('class ')` 分支改为
   `Class::for_class(String::from("<binary name>"))`，栈类型标为 `Class`。
2. `codegen/transpile.py`：新增 `_CLASS_CLASS = 'java/lang/Class'`，ldc 类字面量把
   `java/lang/Class` 加入 `field_discover_classes`，保证 `Class` 类型在闭包。
   （ldc 引用的目标类**不需要**进闭包 —— `Class` 对象只承载 binary name。）
3. `runtime/java_runtime/src/java/lang/class_impl.rs`：
   - `for_class(binary_name) -> Class`：thread_local + HashMap 缓存，保证
     `X.class == X.class` 的身份语义；name 存 Java 形式（`/` → `.`）。
     注意**不返回 `Result`**——否则与局部变量类型 `Class` 不匹配。
   - `__impl_getName`：`java/lang/Class` 是类型存根，字节码版 `getName()` 是 stub。
   - `__impl_desiredAssertionStatus`：恒 `false`（JVM 默认禁用断言）。

**关键连锁效应**：修好 ldc 后，JDK 大量类 `<clinit>` 里的

```java
static final boolean $assertionsDisabled = !X.class.desiredAssertionStatus();
```

从「null 接收者 → 静默 false」变成「真实调用 → stub panic」。
`desiredAssertionStatus` 手写为 false 后恢复。**改 ldc 必须连带处理此方法。**

结果：`TestClassLiteral` 的 `getName()` 与 `Class` 身份比较已输出正确值；
`isAssignableFrom` 仍 FAIL（见 R1）。

### C1 与 C2 同源，需统一设计

实测 `downcast` 与 `From<Object>` 是同一族问题——都在 runtime 的**类型转换系统**：

```
List<Object>: From<ArrayList<_>>            （容器 → 接口的协变转换）
Function<Object,Object>: From<Object>       （Object → 函数式接口）
String.downcast::<String>()                 （checkcast 的类型还原）
```

三者都需要先确定「`Object` 如何承载任意 Java 引用」以及「具体类型之间如何互转」，
不宜各自打补丁。建议作为一个整体设计项推进，再逐个解锁 12 + 6 个编译失败。

> 注：`build/target/debug/` 下部分 binary 可能陈旧于当前生成源码，
> 统计以重新全量构建（`python3 scripts/run_tests.py`）为准。
