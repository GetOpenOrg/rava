## 一、项目坐标与终局定义

**换挡点判断（2026-09-23）**：语义修复浪潮近收尾（G-3 合入后服务器清单预期仅剩 VirtualThread），架构收敛完成前半程（TypeIR 最小层 + 批次 2 落地，A-4/A-5/downcast 链主战役收官）——项目正从「修测试时代」换挡到「定型时代」：主要工作从消除失败转为收敛形态、固化规格、准备重写。

**终局三性质**（既有文档共识的提炼）：

1. **正确性**——golden 差分验证，e2e 全量绿（169 语料，差分 + 失败棘轮 + [run-classify] 自动归类）。
2. **可读性**——生成物是给人读的 Rust（vtable 分派、无 borrow/downcast 噪音）；禁令最终由生成器内建 `lint` 子命令 + CI 保证 0 命中，从纪律变测试。
3. **可维护性**——类型决策集中 ≤3 个文件（类型模型 + 宏 + render），IR 是唯一货币；终态交付**单二进制 `java-rta`**，Python 归零。

## 二、三条主线

### 主线 1：架构收敛线（当前最重）

沿收敛路线图五层阶梯推进，余量自上而下：

| 层 | 已完成 | 远期余量 |
|---|---|---|
| L1 类型模型 | TypeIR 最小层（`jvm_type.py` + 35 单测）；批次 2 六消费点（type_surgery 69→27） | **批次 3**（invoke_sig 5 + invoke_virtual 4，余量大头）→ **M-3 试点**（签名决策进宏——「Python 时代做、Rust 时代全额继承」的头号保留性投资）→ T-1 bounds 进宏 |
| L2 类型位置 | A-4 载体化主战役（Into\<I\> −49%）；downcast 链移除 | T-4 包装类走生成；R-2 Deref 替代 From 继承链（R-1 已落地，低风险随时可做） |
| L3 转换 IR 化 | A-3（CastExpr 样板，12 处字符串发射删除） | **窗口 3**：G-1/G-2/G-3 迁 rs_ir——最后一个大 Python 内部重构（G-3 调查即其前置侦察，WIP 已静态验收）；其后转换族逐个 IR 化至 RawExpr/RawStmt→0 |
| L4 分派/对象模型 | A-5 lambda 对象化；downcast 链根方法直调 | 抽象类/枚举/手写类 `__interface` 覆盖收尾（A-6 残余） |
| L5 治理 | 五审计线 + equiv/deny 机器 + 双种子确定性 | 度量自动化维持，趋势门禁只降不升 |

**本线终点 = Rust 重写起点**。三信号门槛：G-4 ✅、窗口 0–2 ✅，剩窗口 3、P-1 清零、门槛①口径（见 §四-1）。

### 主线 2：语义覆盖线（决定「像不像 JVM」）

近期收尾后余下的是**深度递增**的语义层，管理模式统一为「调查先行 + 等价显式化」：

1. **VarHandle 引用族**（在队）——unsafe-cell 家族第四例（`__unsafe_ref_cell`），CompletableFuture 无锁完成栈依赖；
2. **VirtualThread / ContinuationSupport**（服务器最后一例，深浅未知）——调查结论同时是 §四-2 线程模型决策的输入；
3. **近似等价边界存量**（S-2 null 数组 / S-3 装箱 null / S-7 record hashCode / S-9 NPE / S-10 类初始化 / S-11 InternalLock）——均已标注于 compatibility.md 且有 `--deny` 升级路径；远期按语料需求逐条收口，**防无底洞**是本 backlog 的管理原则；
4. **反射 L3**（Method 分派协议与 A-4/TypeIR 合流）——元数据表 L1/L2 已落地（build.rs 四表 + getDeclaredMethod/getDeclaredField 转正）；
5. **JDK25 语料适配**——不只是修 17 个错，是「版本健壮性」首次实测：验证信息从 .class 元数据动态解析（与 P-1 同源），而非字面量表。

### 主线 3：验证与治理线（远期质量的承重墙）

- **语料扩张**：169 定向语料是当前基准；「新错误族月级」信号的可信度取决于语料代表性——远期引入 1–2 个真实小型开源项目做 pilot 语料（决策见 §四-3）；
- **golden 基建前置**：重写 R0 的 corpus + token 级 diff 工具**从现在开始攒**（每轮 e2e 顺手固化生成物快照），重写启动时零成本；
- **惯犯块纯核提取**（invoke_sig / coerce / stack / vars）——收敛路线图处方 3：既是耦合解药（四次事故史），也是 Rust 移植预制品（纯核 ≈ 未来 crate 函数）；
- 文档卫生：tasks.md 陈旧行核销（catch 作用域 2 例随 G-3 关闭、接口槽位 2 例已修、一次性编译错 4 例过半已修）。

### §四-3 附：真实项目 pilot 阶梯（2026-09-23 建议方案，待拍板）

**pilot 定义**：选真实开源 Java 项目，其 jar 的 `.class` 作为转译输入，连同其 JUnit 测试套件一起翻译，用**同一套测试在 JVM 与 Rust 两侧的运行结果**做 golden 对账——169 定向语料之外的真实世界压力面，直接标定「新错误族频率」（R0 信号 c）的可信度。远期指向「迁移 Java 生态 jar → Rust 包」的北极星。

**测试库先行的硬理由**：后续每个 jar pilot 的验证 harness 就是它自带的 JUnit 测试套件——**不先翻译 JUnit/Hamcrest，任何库 pilot 都没有自验证能力**，测试库是地基而非可选项。但**构建工具（Maven/Gradle/Ant）是最差首批目标**：动态类加载容器 + DSL 脚本引擎 + 网络依赖解析 + 守护线程，正打静态闭包翻译模型的死穴，且其价值在编排进程而非库语义，迁移价值密度最低。

| 阶段 | 项目 | 选择理由 | 压测面 |
|---|---|---|---|
| P0 | **JUnit 4.13.2 + Hamcrest 2.2**（选 4 不选 5：5 的 Launcher 机制大得多） | 一切后续 pilot 的验证地基；Hamcrest 极小、纯计算 | Hamcrest `Matcher<T>` 接口族 = A-4/T-2 载体系统的真实消费者；JUnit 注解模型压反射 L1/L2、Runner 机制逼 L3 排期；`@Test(timeout=)` 触线程模型决策 |
| P1 | **commons-lang3**（或 commons-text） | 数百类、纯计算为主、Apache 协议、API 面广 | 字符串/数值输出一致性（S-19 延伸）；`ReflectionToStringBuilder`/`SystemUtils`/Locale 压反射与 runtime |
| P2 | **commons-io** 或 **Jackson core**（streaming） | 文件 I/O / 流式解析器，无 GUI 无网络 | runtime I/O 层深度（现有手写 file/blocker 件的试金石）；Jackson 纯计算、闭包可控 |
| P3 | **Guava 切片**（`collect` 原始集合、`base`）→ 整库 | 生态公认压测标杆 | 10k+ 类闭包、泛型深水区、ListenableFuture → 线程模型决策（§四-2）的实测输入 |
| 远期 | AssertJ / Eclipse Collections / Guice 等 | 按需 | — |

**明确不早期碰**：Maven/Gradle/Ant（类加载容器）、Mockito（Instrumentation agent + 运行时字节码生成，超出静态翻译模型）、Spring（动态代理/AOP）、Netty（unsafe + epoll NIO）。

**逼出的能力缺口（= 工程收益，每个 pilot 阶段自然排期）**：
1. **库模式发射**：jar → lib crate + 公开 API 面映射（当前管线是「单 main 类 → bin」；提前给重写方案 `driver` crate 定义需求）；
2. **driver 的 jar 输入模式**：BFS 语料机制架构上已兼容任意 `.class` 来源（不区分 jmods 与 jar），入口需从「单 .java」扩为「jar + 测试入口清单」；
3. **反射 L3、I/O 深度、时钟/随机确定性沙箱**（golden 可复现的前提）；
4. **线程模型决策提前兑现**：从纸面讨论变实测数据。

**管理预期**：「迁移整个 Java 生态」是北极星不是里程碑——阶梯每步独立产出价值（harness / 压测数据 / 被逼出的能力），失败可停在任意阶。P0/P1 建议插在 S2–S3 间启动，与 M-3/TypeIR 收敛互相验证。
