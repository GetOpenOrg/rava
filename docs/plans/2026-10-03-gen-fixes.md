# 生成器独立缺陷合集（gen-fixes）

分支 `gen-fixes`（起点 origin/rust-closure-analyzer 47df2048）。五项各一步提交，运行期验收由主会话在分布式服务器抽查。
背景：`docs/tasks.md`（hierarchy_overloaded_names 条目）、`docs/reports/e2enew-da8abee1-triage.md`（R4 / R10 / R12、TestClassCastSubclass）。

## 1. hierarchy_overloaded_names 不查接口（E0061）

- **根因**：`TyCtx::overloaded_rec` 的「继承参数段」只沿超类链收集类方法表（接口只计注入的 default），
  接口上声明、类链未实现的抽象成员不计。类自有 `m(String[])` 与接口抽象 `m()` 同名时类不 mangle，
  类内 `this.m()`（invokevirtual 指向只声明在接口上的成员）落到自有一参方法 → E0061。
  实例：`sun/nio/fs/AbstractBasicFileAttributeView.readAttributes`（自有 `readAttributes(String[])`，
  `BasicFileAttributeView.readAttributes()` 抽象），`Files.getAttribute(p, "unix:nlink")` 触发。
- **修法**：`add_unimplemented_interface_members`——ci 及祖先类实现的全部接口（含超接口传递）上的
  非 static / 非 private / 非 synthetic 实例成员，若类链上无同名同描述符方法（含泛型桥）则其参数段并入
  继承参数段。类链已有同描述符实现（含桥）的接口成员由实现承载，不另计——擦除桥不制造重载
  （`Comparable.compareTo(Object)` 与 `compareTo(T)` 不因此 mangle）。定义侧与调用侧同用该判定，
  名字一致。
- **用例**：新增 `tests/e2e/26_interface_advanced/TestOwnOverloadVsInterfaceAbstract.java`
  （直接接口 / 超接口传递 / JDK `Files.getAttribute(p, "unix:nlink")` 三形态；expected 由参考 JDK 21.0.11 双跑一致生成）。

## 2. R12 E0308 ×3（lambda 返回适配 / catch 变量重赋值）

- **TestComparatorNullsFirst**：`Comparator.comparingInt(Item::price)`，实现方法返回 `Integer`、SAM
  （`ToIntFunction.applyAsInt`）返回 `int`。LambdaMetafactory 对返回值做拆箱适配，生成闭包却原样返回
  `Result<Integer>` → E0308。
- **TestStreamTerminalEdges**：`mapToLong(String::length)`，实现返回 `int`、SAM 返回 `long`，
  LMF 做基本类型拓宽（JLS §5.1.2），生成闭包返回 `i32` → E0308。
- **修法（前两例）**：`lambda_body::adapt_return` 按 LMF 返回适配规则补全：基本→基本拓宽生成 `as` 转换；
  引用→基本经 `boxing::unbox_return` 拆箱（实现返回包装类型时调 `xxxValue()`，含拆箱后拓宽；
  返回 `Object` / 泛型擦除时走既有的 `unbox_object_arg`）。
- **TestJndiNoProvider**（E0283，`RemoteObjectInvocationHandler.invoke`）：Java 在 catch 体内重新赋值
  catch 变量 `e = new UnexpectedException(...)`。catch 绑定写在 `Tag::Catch` 结构行头里，
  `promote_undeclared_assigns` 不认作已声明，把重赋值提升成 `let mut e = (...).into();`，类型无从推断。
- **修法**：`Entry::catch_binding` 从 catch 衔接行（`try_plan::catch_head` 格式）取绑定名，
  `promote_undeclared_assigns` 在 catch 体嵌套层登记为已声明，重赋值保持为赋值（catch 绑定本为 `let mut`）。
- **TestJndiNoProvider 第二处**（E0308，`rmiURLContextFactory.getUsingURLs`）：外层 try 体以
  `'l0: loop { … java_try!{ try { …; break 'l0; } … } … }` 结尾。`java_try!` 的落出判定
  `BreakScan` 只认无标签 break，内层 try（已展开为标签块）里跳出本循环的 `break 'l0` 不计，
  循环被判为 `!`、省掉尾随的 `break 'java_try_end_N`，循环成为 `JvmError` 块的尾表达式。
  **修法**：`BreakScan` 同时计入带本循环标签的 break（任意嵌套深度）；单测
  `labeled_break_to_loop_falls_through`。
- **验证**：三例 emit + `rava compile` 通过；单测 `catch_binding_parses_head`。

## 3. 数组协变：`Object[].class.isAssignableFrom(Integer[].class)`（TestClassCastSubclass）

- **根因**：手写 `Class.isAssignableFrom` 只查 `meta::class_hierarchy()` 的超类型表；数组类不在表中，
  退化为同名相等，`Object[] ← Integer[]`、数组 → `Object` / `Cloneable` / `Serializable` 均判 false。
  同一语义在 checkcast / 反射数组组件标签处已由 `Class::__name_assignable` 承载（含数组协变规则）。
- **修法**：`isAssignableFrom` 统一走 `__name_assignable`（单一真源）：null 实参 → NPE；同名 → true；
  任一侧为基本类型类 → false（基本类只与自身相容，`Object ← int` 为 false）；其余引用类型（含多维、
  基本元素数组须同元素）交 `__name_assignable`。
- **用例**：新增 `tests/e2e/62_reflection/TestArrayClassAssignability.java`（协变 / 逆向 / 多维 /
  `Object[] ← int[][]` / 基本元素数组 / 数组 → Object·Cloneable·Serializable / 基本类型类 / null → NPE）。
- **验证**：TestClassCastSubclass 与新用例 emit + `rava compile` 通过。

## 4. R10 `Array.get/set` 系 native（TestReflectArrayDeep）

- **根因**：`java/lang/reflect/Array` 只手写了 `newArray` / `getLength` 等，`get` / `set` 及
  `getXxx` / `setXxx` 共 18 个 `ACC_NATIVE` 方法缺实现，运行时命中 native 存根。
- **修法**：`array_impl.rs` 按 JDK `Reflection::array_get / array_set` 语义补齐（ACC_NATIVE，准入类别 ①）：
  - `get`：引用元素原样返回，基本元素经包装类 `valueOf` 装箱（缓存池身份同 JDK）；
  - `set`：引用元素数组按组件类型 `__name_assignable` 存储检查（不符 → IAE "array element type mismatch"，
    null 恒可存）；基本元素数组先拆箱（null → 无消息 IAE，非包装类 → IAE "argument type mismatch"）
    再按 JLS §5.1.2 拓宽写入；
  - `getXxx` / `setXxx`：基本元素按拓宽表读写；引用元素数组 → IAE "Argument is not an array of primitive type"；
  - null 数组 → NPE；非数组 → IAE "Argument is not an array"；越界 → AIOOBE（JArray 承载）。
  手写层扫描器从 `valueOf_*` / 构造调用派生闭包回调边，无需另登记清单。
- **用例**：新增 `tests/e2e/62_reflection/TestReflectArrayAccessEdges.java`（拓宽读写、拆箱、类型不符、
  协变存储检查、null / 非数组 / 越界，异常消息逐条对照参考 JDK）。
- **验证**：TestReflectArrayDeep 与新用例 emit + `rava compile` 通过，precheck `native_missing` 无 `reflect/Array` 项。
