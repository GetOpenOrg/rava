# MH-native：MethodHandle 原生调用模型（#40 / N11）

> 2026-09-26 用户决策启动（此前暂缓：覆盖面仅 RecordsSerializationTest 1 例）。
> 验收用例：`tests/e2e/59_method_handles/TestMethodHandleDirect.java`、
> `TestMethodHandleCombinators.java`（JVM 生成期望），`35_io/RecordsSerializationTest.java`。

## 一、现状与卡点

- `java.lang.invoke` 公开 API（`MethodHandles` / `Lookup` / `MethodType` / 组合子 / LambdaForm 构造）
  全部经字节码翻译，`MemberName` 解析已原生化（`MethodHandleNatives.resolve` 查 build.rs 元数据表）。
- **调用内核缺失**：`MethodHandle.invokeExact / invoke / invokeBasic / linkTo*` 是 ACC_NATIVE 签名多态
  方法，当前为 `panic!("native: …")`——任何句柄调用都不可达。
- **运行期字节码生成被整链翻译**：`LambdaForm.compileToBytecode` → `InvokerBytecodeGenerator`
  （及其 ASM 依赖）进入闭包；原生二进制不能定义隐藏类，这条链既无用又膨胀闭包。

## 二、方案：保留 JDK 组合子字节码，原生化调用内核

JDK 的 MethodHandle 语义完整编码在 LambdaForm（`names[]` 表达式图）里；LambdaForm 本身可解释执行
（JDK 自带 `interpretWithArguments` 解释器路径）。因此：

1. **句柄与组合子保持翻译**（原则 1）：`bindTo` / `insertArguments` / `dropArguments` /
   `filterReturnValue` / `asType` / `guardWithTest` / `asSpreader` / `asCollector` 等全部是
   LambdaForm 构造逻辑，零手写。BMH 物种走 JDK 镜像预生成类（`Species_L … Species_LLLLLLLLL`、
   `Species_I/J/D` 族，ClassSpecializer 按类名先查预生成类）。
2. **`InvokerBytecodeGenerator` 列入 vm_boundary（整类手写）**：`generateCustomizedCode` /
   `generateLambdaFormInterpreterEntryPoint` 返回 null（vmentry 不被原生解释器使用），
   `isStaticallyInvocable*` 恒 true（仅断言消费）。截断 ASM 链。
3. **`invokeBasic` 原生 = LambdaForm 解释器（Rust）**：`values = [mh, args…]`，按 `names[arity..]`
   逐个求值：
   - `function.member` 为 `MethodHandle.invokeBasic` → 递归 invokeBasic；
   - `linkToStatic / Virtual / Special / Interface` → 末参 MemberName 按 refKind 分派（见 4）；
   - 其他 member → 按 (声明类, 名字, 描述符, refKind) 反射分派；
   - 无 member（`resolvedHandle`）→ invokeBasic(resolvedHandle, 实参)。
   结果取 `names[result]`（`VOID_RESULT` → null）。
4. **成员分派 = 反射分派注册表**（与 `Method.invoke` 同一协议 `__reflect_dispatch`）：
   refKind 1–4 字段访问、5 invokeVirtual / 9 invokeInterface（接收者虚分派）、6 invokeStatic、
   7 invokeSpecial、8 newInvokeSpecial（构造器）。JDK 类的分派臂只为「常量反射引用」成员发射
   （见 5），不全量铺开。
5. **常量反射引用播种**（callchain）：闭包内方法字节码中 `ldc Class C` 与 `ldc String s`
   同现且 C 声明名为 s 的方法/字段 → 将 C.s（全部重载）加入 BFS 并登记分派。覆盖 JDK 内部
   以 `IMPL_LOOKUP.findStatic(X.class, "name", …)` / `new MemberName(X.class, "name", …)` 构造的
   LambdaForm 辅助函数，以及用户代码的 `lookup.findVirtual(String.class, "length", …)` 目标。
6. **`invokeExact` / `invoke` 带调用点类型**：签名多态调用点描述符由 codegen 传入
   （`_gen_signature_polymorphic` 已持有），运行时构造调用点 `MethodType`：
   `invokeExact` 类型不等 → `WrongMethodTypeException`；`invoke` → `mh.asType(callType)` 后
   invokeBasic（asType 的适配形态由 JDK 字节码构造）。

## 三、实施步骤

| 步 | 内容 | 验收 |

| 1 | IBG 边界 + 闭包收缩 | TestMethodHandleDirect 转译通过，闭包类数下降 |

## 四、偏差与边界

- 解释执行（无 LambdaForm 编译）：性能低于 JIT 形态，语义等价。
- 预生成物种之外的 BMH 物种（ClassSpecializer 运行期生成）不可达 → 如实报 stub/异常，按用例补。
